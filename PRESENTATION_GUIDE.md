## Текст доклада (5 минут)

### Вступление (30 секунд)

Добрый день! Сегодня я представлю проект по разработке интеллектуального чат-бота для абитуриентов Государственного университета управления на основе технологии RAG — Retrieval-Augmented Generation.

В условиях цифровизации образования абитуриенты сталкиваются с избытком информации, распределенной по разным документам. Традиционные чат-боты не справляются со сложными запросами, а стандартные языковые модели склонны к галлюцинациям и не имеют доступа к актуальным документам вуза.

### Проблема и цель (45 секунд)

**Проблема**: Абитуриентам нужен единый "входной окно", которое работает мгновенно и предоставляет только юридически достоверную информацию.

**Цель нашего исследования**: Разработать прототип интеллектуального Telegram-бота на основе архитектуры RAG и экспериментальным путём подтвердить эффективность данной технологии в повышении точности информирования абитуриентов.

### Технологии (45 секунд)

Наш технологический стек включает:
- Python для разработки
- Sentence Transformers для локальной генерации векторных представлений текста
- Qdrant — специализированную векторную базу данных
- GigaChat API для генерации ответов
- Telegram Bot API как интерфейс взаимодействия

Ключевое преимущество — использование локальной модели embeddings, что позволяет работать без зависимости от внешних API и снижает затраты.

### Архитектура RAG (1 минута 30 секунд)

RAG работает в три этапа:

**Первый этап — Retrieval (Извлечение)**: Когда пользователь задает вопрос, система векторизует запрос и ищет в векторной базе данных Qdrant топ-10 наиболее релевантных фрагментов документов. Поиск происходит по смыслу, а не по ключевым словам.

**Второй этап — Augmentation (Дополнение)**: Найденные фрагменты формируются в контекст, добавляется информация о похожих запросах, если они есть, и готовится промпт для языковой модели.

**Третий этап — Generation (Генерация)**: Контекст отправляется в GigaChat API, который генерирует ответ, опираясь исключительно на предоставленные факты. Это критически важно — модель не может "придумать" информацию, которой нет в документах.

### База знаний и обработка (45 секунд)

Наша база знаний включает:
- 66 документов из папки GUU_docs — это правила приема, программы вступительных испытаний, договоры
- Около 5336 фрагментов из краулинга официального сайта ГУУ

Процесс обработки: документы разбиваются на чанки по 500 слов, векторизуются через Sentence Transformers в векторы размерности 384, и загружаются в Qdrant. Всего в базе около 6000-7000 точек.

### Результаты (45 секунд)

**Производительность**:
- Время поиска: всего 1-5 миллисекунд
- Точность поиска: 95-99%
- Общее время обработки запроса: 0.6-2.6 секунды

**Преимущества**:
- Точность: ответы основаны только на официальных документах
- Актуальность: база обновляется без переобучения модели
- Проверяемость: каждый ответ содержит ссылки на источники
- Снижение галлюцинаций: модель ограничена предоставленным контекстом

### Выводы (30 секунд)

Мы успешно применили RAG-технологию для информационной поддержки абитуриентов. Система обеспечивает высокую точность и скорость работы, готова к использованию в production.

**Перспективы**: масштабирование до миллионов документов, интеграция с другими сервисами университета, добавление мультимодальности.
