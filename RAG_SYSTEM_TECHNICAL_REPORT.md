## Введение

Данный отчет описывает техническую реализацию RAG (Retrieval-Augmented Generation) системы в составе интеллектуального Telegram-бота для информационной поддержки абитуриентов Государственного университета управления (ГУУ).

RAG-система обеспечивает:
- **Точность**: Ответы основаны исключительно на официальных документах ГУУ
- **Актуальность**: База знаний обновляется без переобучения модели
- **Проверяемость**: Каждый ответ содержит ссылки на источники
- **Снижение галлюцинаций**: Модель ограничена предоставленным контекстом

## Архитектура RAG-системы

### Общая схема работы

ПОЛЬЗОВАТЕЛЬ (Telegram)
    |
    | Запрос
    v
MAIN.PY
    |
    | ask_gigachat() - главная функция обработки
    |
    +---> ВЕТВЬ 1: user_queries_storage.search_similar()
    |         |
    |         | Поиск похожих запросов
    |         |
    |         v
    |    Qdrant (user_queries)
    |
    +---> ВЕТВЬ 2: rag_search_vector.search()
            |
            | Векторный поиск
            |
            v
        Qdrant (guu_documents)
            |
            | Топ-10 результатов
            |
            v
        Формирование контекста
            |
            v
        GigaChat API - Генерация ответа
            |
            v
        Форматирование + Источники
            |
            v
        Сохранение запроса в user_queries

### Три этапа RAG

1. **Retrieval (Извлечение)**
   - Векторизация запроса пользователя
   - Семантический поиск в векторной БД Qdrant
   - Получение топ-10 наиболее релевантных фрагментов документов

2. **Augmentation (Дополнение)**
   - Формирование контекста из найденных фрагментов
   - Добавление информации о похожих запросах (если есть)
   - Подготовка промпта для LLM

3. **Generation (Генерация)**
   - Отправка контекста и запроса в GigaChat API
   - Генерация ответа на основе предоставленных данных
   - Форматирование ответа с указанием источников

### 3. Скрипт миграции данных (`rag_build_vector.py`)

**Назначение**: Загрузка данных из JSON индекса в векторную БД Qdrant

**Входные данные**:
- Файл: `data/guu/index.json`
- Формат: JSON массив объектов
- Количество записей: ~5336 чанков (из краулинга сайта) + ~762 (из документов)

**Процесс миграции**:

```python
def main():
    # 1. Инициализация модели embeddings
    model = get_model()  # Загрузка Sentence Transformer
    
    # 2. Подключение к Qdrant
    client = QdrantClient(host="localhost", port=6333)
    
    # 3. Загрузка индекса
    index = load_index("data/guu/index.json")  # ~5336 чанков
    
    # 4. Создание коллекции
    create_collection(client, "guu_documents", vector_size=384)
    
    # 5. Векторизация и загрузка батчами
    vectorize_and_upload(client, index, batch_size=20)
```

**Алгоритм векторизации**:

1. **Батчинг**: Данные обрабатываются батчами по 20 текстов
   - Причина: Оптимизация использования памяти и скорости
   - Векторизация батча занимает ~0.1-0.2 секунды

2. **Преобразование ID**: 
   - Входной формат: `"chunk000123"` (строка)
   - Выходной формат: `123` (число)
   - Оригинальный ID сохраняется в `payload.chunk_id`

3. **Загрузка в Qdrant**:
   - Используется метод `client.upsert()`
   - Все точки загружаются одной операцией после векторизации всех батчей
   - `wait=True` обеспечивает синхронность операции

**Обработка ошибок**:
- Если батч не удалось обработать, скрипт продолжает со следующим
- Ошибки логируются, но не останавливают процесс
- Финальная проверка: вывод количества загруженных точек

### 4. Модуль векторного поиска (`rag_search_vector.py`)

**Назначение**: Семантический поиск релевантных документов по запросу пользователя

**Класс `VectorRagSearcher`**:

```python
class VectorRagSearcher:
    def __init__(self, qdrant_host, qdrant_port, collection_name):
        # 1. Подключение к Qdrant
        self.client = QdrantClient(host=qdrant_host, port=qdrant_port)
        
        # 2. Проверка существования коллекции
        collections = self.client.get_collections()
        if collection_name not in collections:
            raise RuntimeError("Коллекция не найдена")
        
        # 3. Предзагрузка модели embeddings
        get_model()  # Ленивая загрузка
    
    def search(query: str, top_k: int = 10) -> List[RagHit]:
        # 1. Векторизация запроса
        query_vector = get_embeddings([query])[0]
        
        # 2. Поиск в Qdrant
        results = self.client.search(
            collection_name="guu_documents",
            query_vector=query_vector,
            limit=top_k,
            score_threshold=0.0
        )
        
        # 3. Преобразование результатов
        hits = [RagHit(...) for result in results]
        return hits
```

**Структура результата `RagHit`**:
```python
@dataclass
class RagHit:
    id: str              # Оригинальный chunk_id
    title: str           # Название документа
    source: str          # Путь к источнику
    content: str          # Текст чанка
    score: float          # Косинусная близость (0.0 - 1.0)
```

**Параметры поиска**:
- **top_k**: 10 (количество возвращаемых результатов)
- **score_threshold**: 0.0 (минимальный порог релевантности)
- **Метрика расстояния**: Cosine Similarity
- **Алгоритм поиска**: HNSW (Hierarchical Navigable Small World)

**Форматирование контекста**:

Метод `format_context()` преобразует результаты поиска в формат для промпта:

```
chunk000123|Правила приема|https://guu.ru/...|page:1|score:0.856|quote:"Текст цитаты..."
```

## Процесс подготовки данных

### Этап 1: Извлечение текста из документов

**Скрипт**: `process_guu_docs.py`

**Алгоритм**:

1. **Сканирование директории `GUU_docs/`**:
   ```python
   for file in os.listdir("GUU_docs"):
       if file.endswith(".pdf"):
           text = extract_text_from_pdf(file)
       elif file.endswith(".docx"):
           text = extract_text_from_docx(file)
       elif file.endswith(".xlsx"):
           text = extract_text_from_xlsx(file)
   ```

2. **Извлечение текста**:
   - **PDF**: `PdfReader` → `page.extract_text()` для каждой страницы
   - **DOCX**: `Document` → `paragraph.text` для каждого параграфа
   - **XLSX**: `pandas.read_excel()` → преобразование в строку

3. **Очистка текста**:
   - Удаление лишних пробелов
   - Нормализация переносов строк
   - Удаление служебных символов

### Этап 2: Разбиение на чанки

**Функция**: `chunk_text(text: str, chunk_size: int = 500)`

**Алгоритм**:
```python
words = text.split()  # Разбиение на слова
chunks = []
current_chunk = []

for word in words:
    current_chunk.append(word)
    if len(current_chunk) >= chunk_size:
        chunks.append(" ".join(current_chunk))
        current_chunk = []

if current_chunk:  # Остаток
    chunks.append(" ".join(current_chunk))
```

**Параметры**:
- **chunk_size**: 500 слов
- **Перекрытие**: Нет (для упрощения)
- **Минимальный размер**: Если документ < 100 слов, создается один чанк

**Почему 500 слов?**:
- Оптимальный баланс между контекстом и точностью поиска
- Слишком большие чанки → низкая точность (много лишнего)
- Слишком маленькие → потеря контекста

### Этап 3: Векторизация и загрузка в Qdrant

**Скрипт**: `process_guu_docs.py` (прямая загрузка) или `rag_build_vector.py` (из JSON)

**Процесс**:

1. **Создание коллекции**:
   ```python
   client.create_collection(
       collection_name="guu_documents",
       vectors_config=VectorParams(
           size=384,  # Размерность вектора
           distance=Distance.COSINE  # Метрика расстояния
       )
   )
   ```

2. **Векторизация батчами**:
   ```python
   for i in range(0, len(chunks), batch_size=20):
       batch = chunks[i:i+20]
       embeddings = get_embeddings(batch)  # ~0.1-0.2 сек
       
       points = [
           PointStruct(
               id=chunk_id,
               vector=embedding,
               payload={...}
           )
           for chunk_id, embedding in zip(chunk_ids, embeddings)
       ]
   ```

3. **Загрузка в Qdrant**:
   ```python
   client.upsert(
       collection_name="guu_documents",
       points=points,
       wait=True  # Синхронная операция
   )
   ```

**Время обработки**:
- 1 документ (50 страниц): ~2-5 секунд
- 66 документов: ~5-10 минут
- Векторизация: ~0.1 сек на батч из 20 текстов
- Загрузка в Qdrant: ~0.05 сек на батч

### Алгоритм поиска HNSW

**HNSW (Hierarchical Navigable Small World)** — алгоритм приближенного поиска ближайших соседей

**Принцип работы**:
1. Построение многоуровневого графа
2. На верхних уровнях — мало связей (быстрый поиск)
3. На нижних уровнях — много связей (точный поиск)
4. Поиск начинается с верхнего уровня, спускается вниз

**Параметры**:
- **ef_construct**: 200 (количество кандидатов при построении)
- **m**: 16 (количество связей на уровне)
- **ef_search**: 128 (количество кандидатов при поиске)

**Производительность**:
- Поиск топ-10: ~1-5 мс
- Точность: ~95-99% (по сравнению с точным поиском)

### Размеры данных

**Коллекция `guu_documents`**:
- Количество точек: ~6000-7000
- Размер вектора: 384 × 4 байта = 1536 байт на вектор
- Размер payload: ~500-2000 байт на точку (в зависимости от длины текста)
- **Общий размер**: ~10-15 MB

**Коллекция `user_queries`**:
- Количество точек: Растет со временем

**Общий размер `qdrant_storage/`**:
- Данные: ~15-20 MB
- Индексы HNSW: ~5-10 MB
- WAL (Write-Ahead Log): ~1-2 MB
- **Итого**: ~20-30 MB

#### Этап 1: Получение запроса

**Обработка**:

#### Этап 2: Поиск похожих запросов

**Функция**: `user_queries_storage.search_similar_queries(query, top_k=3)`

**Алгоритм**:

#### Этап 3: Векторный поиск в документах

**Функция**: `rag_search_vector.VectorRagSearcher.search(query, top_k=10)`

**Детальный алгоритм**:

1. **Векторизация запроса**:
   ```python

   # Размерность: 384

   ```

2. **Поиск в Qdrant**:

   ```python
       collection_name="guu_documents",
       query_vector=query_vector,
       limit=10,
       score_threshold=0.0,
       search_params={"hnsw_ef": 128}
   )
   # Время: ~1-5 мс
   ```

3. **Обработка результатов**:

   ```python
   hits = []
   for result in results:
       hits.append(RagHit(
           id=result.payload["chunk_id"],
           title=result.payload["title"],
           source=result.payload["source"],
           content=result.payload["content"],
   ```

**Интерпретация score**:
- **0.9-1.0**: Очень высокая релевантность (почти точное совпадение)
- **0.7-0.9**: Высокая релевантность (хорошее совпадение)
- **0.5-0.7**: Средняя релевантность (частичное совпадение)

## Сохранение запросов пользователей

### Назначение

Сохранение запросов пользователей позволяет:
1. **Улучшение ответов**: Поиск похожих запросов и использование их ответов
2. **Аналитика**: Понимание, какие вопросы задают чаще всего
3. **Персонализация**: Учет истории запросов пользователя

### Архитектура

**Коллекция**: `user_queries`

**Структура точки**:
```python
PointStruct(
    id: int,  # Уникальный ID (timestamp * 1000000 + user_id)
    vector: List[float],  # Вектор запроса (384)
    payload: {
        "user_id": int,
        "query": str,
        "response": str,
        "timestamp": str,  # ISO format
        "type": "user_query",
        ...  # Дополнительные метаданные
    }
)
```

### Процесс сохранения

**Функция**: `UserQueriesStorage.save_query(user_id, query, response, metadata=None)`

**Алгоритм**:

1. **Векторизация запроса**:
   ```python
   query_vector = get_embeddings([query])[0]
   # Размерность: 384
   ```

2. **Формирование payload**:
   ```python
   payload = {
       "user_id": user_id,
       "query": query,
       "response": response,
       "timestamp": datetime.now().isoformat(),
       "type": "user_query"
   }
   if metadata:
       payload.update(metadata)
   ```

3. **Генерация уникального ID**:
   ```python
   point_id = int(time.time() * 1000000) + user_id
   # Микросекунды + user_id для уникальности
   ```

4. **Сохранение в Qdrant**:
   ```python
   client.upsert(
       collection_name="user_queries",
       points=[PointStruct(id=point_id, vector=query_vector, payload=payload)]
   )
   ```

### Поиск похожих запросов

**Функция**: `UserQueriesStorage.search_similar_queries(query, top_k=5, user_id=None)`

**Алгоритм**:

1. **Векторизация запроса**:
   ```python
   query_vector = get_embeddings([query])[0]
   ```

2. **Поиск в Qdrant**:
   ```python
   results = client.search(
       collection_name="user_queries",
       query_vector=query_vector,
       limit=top_k
   )
   ```

3. **Фильтрация по user_id** (если указан):
   ```python
   if user_id is not None:
       results = [r for r in results if r.payload["user_id"] == user_id]
   ```

4. **Формирование результата**:
   ```python
   return [{
       "query": payload["query"],
       "response": payload["response"],
       "user_id": payload["user_id"],
       "timestamp": payload["timestamp"],
       "score": result.score
   } for result in results]
   ```

   - Выбор оптимального размера для конкретных документов

5. **Фильтрация по метаданным**:
   - Поиск только в определенных типах документов
   - Ускорение: ~20-30% при использовании фильтров
